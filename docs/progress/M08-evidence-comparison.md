# M08 — Evidence-based candidate/reference comparison

## Status

**Implemented and demonstrated using the latest M07 candidate output and stored provider evidence.** The comparison contract produces one candidate-to-reference pair for each candidate and each record in the authoritative 31-site `reference-sites.json`. It is a descriptive evidence matrix; it does not calculate similarity, mission suitability, confidence, weights, rankings, or a best analog.

## Architecture and method

- `src/comparison/compare.ts` contains pure comparison functions and versioned output validation.
- `scripts/run-comparison.ts` loads the latest discovery run, 31 references, stored NASA POWER histories, GLO-30 samples, and GLiM normalized records. It does not make external requests.
- `scripts/validate-comparison.ts` validates the pair matrix against the authoritative reference inventory, candidate list, fixture separation, metadata, and forbidden score/rank fields.
- `tests/comparison.test.ts` covers compatibility, missingness, source failures, classifications, elevation metadata, regions, multiple records, reproducibility, provenance, and forbidden scoring outputs.
- Outputs are under `data/processed/comparison-runs/`: `latest.json`, a unique UUID archive, and `validation-report.json`.

Climate comparisons require NASA POWER histories with matching 2001–2020 observation periods and matching parameter units. Daily histories use candidate-minus-reference differences at q25, median, and q75 with valid/missing observation counts and temporal coverage. Summary-only inputs use a separately labeled period-mean difference only when both histories are absent and the source/period/unit agree. Temperature range is derived from valid daily `T2M_MAX - T2M_MIN` values. These are descriptive distribution comparisons, not similarity measures.

For compatible histories, climate factor records also include compact temporal summaries: local-hemisphere three-month calendar seasons and calendar-year means, with expected, valid, and missing day counts and coverage. They do not duplicate daily histories in the pair matrix. The UI labels these as descriptive calendar-season summaries, not mission-specific climatic seasons. Exact period and units must still match before comparison.

Geology comparisons preserve GLiM levels `xx`, `yy`, and `zz` separately and compare only exact codes at the same level. Multiple intersecting features remain `ambiguous`. Explicit No Data classes and placeholder `__` levels are preserved in source evidence and not counted as a shared lithology match. No mineral information is inferred.

Elevation can only be compared as a point-sample difference in meters when both GLO-30 samples include compatible vertical metadata. It is never called terrain similarity. Missing terrain metrics, UV, mineralogy, surface material fractions, regolith, and subsurface evidence remain unavailable. Failed candidate providers remain `failed`, separate from unavailable/missing evidence.

The compared factors are eight climate dimensions (seven NASA POWER parameters plus derived daily temperature range) and two compatible GLiM levels (`xx`, `yy`) for each of eight references with matching evidence. `zz` placeholder codes are not treated as a match. The 31 failed factors are the candidate point-elevation comparisons after the candidate Copernicus failure; unsupported dimensions and references without matching data remain unavailable. No raw climate history is duplicated into pair records; stable processed paths and provenance are referenced.

## Reproduction

```powershell
npm.cmd run discover:candidates
npm.cmd run validate:discovery
npm.cmd run compare:candidates
npm.cmd run validate:comparison
```

For a clean checkout with network access and no cached raw data, retrieve the configured original-site and supplementary provider records first, then rebuild and validate references. The README lists that full ingestion sequence. `compare:candidates` itself is offline and uses the saved normalized histories.

## Limitations and next scientific work

- Only eight of 31 references currently have the compared climate/GLiM point evidence, and the candidate has no usable GLO-30 sample.
- Five original atlas sites have approximate coordinates; supplementary point coordinates describe study areas/pavements/spring clusters with their own uncertainty.
- NASA POWER is gridded, GLiM is generalized mapping, and GLO-30 is a DSM. Source differences do not validate analog status.
- There is no validated factor normalization, scientific weighting, or calibration dataset. Any future numerical ranking requires expert-selected methods, independent positive and contrast/control examples, coordinate-aware holdout design, and external scientific review.

No M09 work is included.

## Separate Mars observational evidence context

Curiosity REMS MODRDR air-temperature evidence is presented by a separate `/mars-evidence` experience and `/api/mars-evidence/rems` artifact. This does not change the historical M08 comparison calculations or turn REMS and NASA POWER into compatible paired observations. Their different measurement basis, height, sampling cadence, and periods are explicitly shown; no cross-source numeric difference or analog suitability result is produced.
